# 阿花 v1.0.1 接管卡顿修复

用户报告：F6接管阿花后，整体画面和操作严重卡顿。性能修复已应用到当前项目启动器，并完成性能与缓存身份专项验收。

## 原因与修复

交互入口沿用了早期初始化诊断配置，关闭了UE4SS对象查询缓存；每帧约42次全局对象查找反复遍历GUObjectArray，阻塞游戏线程。

`tools/pbz_ue4ss_baseline.py`现在为已验证的交互入口启用加载器原生对象缓存，由原生删除监听器清除失效条目。初次无Mod初始化诊断仍关闭缓存。租约、构建、对象完整身份、引擎有效性、控制权、生命、主角输入屏障、视线、距离和恢复检查全部保留。

游戏Lua与自编译DLL没有修改，完整28能力/29绑定仍使用已安装的`ahua-28-v1-b823a4c9b91b404a`。v1的完整能力与600秒验收继续作为该游戏源码的证据；本次另补性能对照、持续接管、取消与缓存生命周期回归，不把旧运行配置的证据冒充新配置实测。

## 实机性能对照

同一核定游戏构建、同一研究存档、相同Mod Lua，仅切换缓存配置；两轮均使用同一只读计时探针。统计剔除了混合进入/退出及加载窗口。原始部署设置哈希已核对，两份设置只有缓存开关不同。

| 指标 | 修复前 | 修复后 |
|---|---:|---:|
| 游戏线程回调频率 | 2.64次/秒 | 82.46次/秒 |
| Mod每帧平均回调耗时 | 364.97毫秒 | 2.50毫秒 |
| 对象查找平均耗时/帧 | 362.20毫秒 | 0.17毫秒 |
| 稳态采样 | 41.626秒、110帧 | 330.4秒、27245帧 |

Mod平均回调耗时降低99.31%。这里的频率来自每个EngineTick一次的回调计数，不是GPU呈现帧率测量。修复后计时探针本身也包含在上述耗时内，日常启动默认不开探针。

## 使用

当前工作目录已应用启动器修复。双击`D:\mod文档\开始阿花训练.cmd`，按原来的准备、云同步关闭确认、启动、进场启用步骤即可。F6接管，WASD移动，鼠标转向，F7切目标，F10恢复。完整键位见第37号操作卡。

仅支持当前核定PBZ构建与本机现有隔离启动器；完整分发包同时包含原v1 Mod和启动器修复，安装Mod文件本身不会更新其他项目副本的启动器。正式游戏及存档不安装Mod，不回写研究进度，也不自动回档。

性能对照报告：`evidence/adaptation/ahua-performance-comparison.json`。最终专项验收：`evidence/adaptation/ahua-performance-hotfix-acceptance.json`。完整28能力Mod与启动器修复组合包在`releases/ahua-v1.0.1-performance-*`目录，包含逐文件哈希及ZIP校验；该目录内`Mod`才是Mod安装管理器可选择的包目录。
